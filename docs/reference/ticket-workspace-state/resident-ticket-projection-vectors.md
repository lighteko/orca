# Resident ticket projection vectors

**Status: independently reviewed logical-v1 vectors for injected code; production proof remains open.** These vectors pin projection outcomes from one validated `TicketCatalogV1`. They do not establish a production service, current source, physical-host mapping, Orca workspace match, or click authority. The contract evidence is pinned at ticket-workspace `54477c2371094f1cbc438845fdfde0ca3584e2aa`.

## Proven source facts

- `TicketCatalogV1` has ticket disposition/lifecycle/coordinator refs and repository `actualRole`, `actualState`, optional transition/current `workspaceRef`, and orchestration correlation. Its validator accepts retained refs on `pruned` rows; the strict schema does not turn a retained ref into eligibility. See [`ticket-catalog-v1.ts`](../../../ticket-workspace/packages/contracts/src/ticket-catalog-v1.ts#L35), [`ticket-workspace-resource-v1.ts`](../../../ticket-workspace/packages/contracts/src/ticket-workspace-resource-v1.ts#L284), and [`ticket-contract-validator-v1.ts`](../../../ticket-workspace/packages/contracts/src/ticket-contract-validator-v1.ts#L143).
- `OrcaOrchestrationCorrelationV1.executionHostId` and both `WorkspaceRefV1.executionHostId` fields are generic bounded `Identifier` strings. The pinned examples use `local`, `host-wsl`, and `machine-alice`; Orca's separate `ExecutionHostId` type is `local | ssh:* | runtime:*`. The ticket source does not define orchestration IDs as physical-host authority or provide a mapping to Orca hosts. A string equality, prefix, or matching path cannot supply that missing mapping. See [`ticket-navigator-snapshot-primitives-v1.ts`](../../../ticket-workspace/packages/contracts/src/ticket-navigator-snapshot-primitives-v1.ts#L31), [the plan fixture](../../../ticket-workspace/packages/cli/test/ticket-workspace-plan-v1.test.ts#L231), [the CLI fixture](../../../ticket-workspace/packages/cli/test/ticket-workspace-cli.test.ts#L1434), [Orca `ExecutionHostId`](../../../src/shared/execution-host.ts#L5), and [`coordinator-root-authority.md`](./coordinator-root-authority.md#L17).
- The snapshot schema already has optional `coordinatorTarget` and workspace `target`, ticket `availability`, workspace `referenceState`, and action arrays. It has no disposition or role-transition field. The full validator checks canonical `snapshotRevision` (excluding that field), SSH presentation, uniqueness, and the 2 MiB UTF-8 bound. See [`ticket-navigator-snapshot-v1.ts`](../../../ticket-workspace/packages/contracts/src/ticket-navigator-snapshot-v1.ts#L47) and [`ticket-navigator-snapshot-validator-v1.ts`](../../../ticket-workspace/packages/contracts/src/ticket-navigator-snapshot-validator-v1.ts#L42).
- Pinned admission returns whole-snapshot `unsupported` when any ticket is marked unsupported. It compares lower `(ledgerRevision, projectionSequence)` against supplied current values, but has no durable high-water store and does not reject an equal pair with a different `catalogDigest`. The latter was confirmed by recomputing `snapshotRevision`: the current helper still admits that candidate. See [`ticket-navigator-snapshot-admission-v1.ts`](../../../ticket-workspace/packages/contracts/src/ticket-navigator-snapshot-admission-v1.ts#L45).
- The existing `snapshot.full` corpus row passes snapshot validation despite `projectionSequence: 1`, a source `generatedAt`/`staleAfter` interval of 11 minutes, and `repositoryId: common-api` versus `target.repoId: repo-1`. It is therefore not a positive Orca owner-match vector. Orca's owner join requires the repository/ref IDs to agree; the positive examples below correct that mismatch synthetically. See [`ticket-navigator-snapshot-v1.corpus.json`](../../../ticket-workspace/packages/contracts/fixtures/ticket-navigator-snapshot-v1.corpus.json#L100) and [`workspace-owner-boundary.md`](./workspace-owner-boundary.md#L10).

## Logical-v1 policy used by these vectors

Use **separate exact allowlists** injected by authenticated setup and bound to the configured profile tuple, authority, epoch, and Orca execution host:

```text
allowedOrchestrationIds = { "orch-profile-A" }
allowedReferenceHostIds = { "ref-profile-A" }
```

Those are synthetic ticket identifiers. Membership means only this exact ticket ID is approved by the injected setup mapping for this configured local-only projection. It does not make the ticket field itself physical-host proof. Production use still needs evidence that setup's mapping is authenticated, complete, and correct. A wrongly allowlisted remote ID is invisible to string membership checks; a local ID missing from the set fails closed.

Apply the decision order below to the same parsed catalog read:

1. Check the ticket orchestration ID, every repository orchestration ID, coordinator-ref host ID, and every current workspace-ref host ID against their respective sets. Any nonmember makes that ticket `availability: "unsupported"`, even if it has no refs or P4 will suppress its refs. Do not classify by `ssh:` prefix alone.
2. Apply target suppression. Ticket `disposition: pruning|pruned` or `lifecycle: tearing-down|removed` omits coordinator and all workspace targets; every workspace `referenceState` is `unavailable`. Otherwise suppress only a workspace target whose current `actualRole` is `excluded`, `actualState` is `absent|removing`, or transition `targetRole` is `excluded`. Keep current `workspaceRef` for other transitions, including target `isolated` or `referenced`; never copy `transition.targetWorkspace` as a current ref.
3. For an unsuppressed, allowlisted current ref, copy the `WorkspaceRef` claim into `target` and set `referenceState: "unavailable"`. For an unsuppressed nonmember workspace ref, omit `target` and set `referenceState: "unsupported"`. A missing ref has no target and `referenceState: "unavailable"`. P4 suppression takes precedence for the row state (`unavailable`), while any P5 failure remains on ticket `availability`.
4. Preserve display rows and source order. `availability: "available"` means the validated row can be displayed; it does not mean a target is eligible, matched, live, or actionable. Emit no actions and never emit `referenceState: "matched"`. A target is a ticket-owned claim for a later Orca-owned binder; it is not a navigation destination. If any ticket is unsupported, the whole snapshot is unsupported, including its otherwise local claims.

No snapshot schema change is required for these choices: existing optional targets encode omission, and existing status fields encode display/unavailability. The v1 snapshot has no coordinator-specific match state; omitting `coordinatorTarget` is sufficient to prevent a coordinator join. Initial owner match and each click still require Orca's fresh same-lease read and exact owner join.

For this packet, an unsuppressed nonmember ref is omitted from `target` and marked unsupported on its workspace row (T6/T10). This deliberately chooses omission over the older historical candidate that retained an SSH target as an unsupported claim; whole-snapshot admission still rejects either shape.

## Catalog-to-snapshot field mapping

| Snapshot field | Projection input/rule |
| --- | --- |
| `source.authorityId`, `ledgerEpoch`, `ledgerRevision` | Copy from the validated catalog. `projectionSequence` is always `0` for this catalog-only projection. |
| `source.catalogDigest` | SHA-256 of canonical JSON for the validated parsed catalog value, not the raw input bytes. |
| `snapshotRevision` | Ticket validator's canonical snapshot digest excluding `snapshotRevision` itself. |
| `producer` | `name: ticket-workspace`, `contractVersion: 1`; `version` must be the exact authenticated/verified resident service artifact version, not copied from catalog metadata by assumption. |
| `profile` | Copy the catalog profile tuple. |
| `generatedAt`, `staleAfter` | `generatedAt` is immediately after the fresh validated read, UTC with milliseconds; `staleAfter = generatedAt + 60,000 ms` on that same source clock. These are source metadata, not Windows currentness proof. |
| Ticket row | Copy `ticketKey`, `title` as `label`, `lifecycle`, and ticket orchestration correlation. Copying `title` preserves its validated 1,024-byte label bound; prepending the key could overflow it. Set enrichment to `{ issue: "unknown", mergeRequests: "unknown" }`; actions `[]`. |
| `coordinatorTarget` | Copy current `coordinatorRef` only when P4 permits it and its host ID is in `allowedReferenceHostIds`; otherwise omit. Never treat it as Orca Run/pane proof. |
| Workspace row | Copy `repositoryId`, `displayName` as `label`, current `actualRole` as `role`, `actualState`, and optional `branch`. Repository orchestration IDs are P5 inputs, not snapshot workspace fields. `desiredRole`, transition, locations/paths, and disposition are not projected. |
| Workspace `target` | Copy the current `workspaceRef` only when P4 permits it and its host ID is in `allowedReferenceHostIds`; otherwise omit. Require `target.repoId === repositoryId` before any Orca mapping; the catalog validator itself does not enforce this relation. |

## Currentness, high-water, and byte boundaries

| Case | Expected v1 decision |
| --- | --- |
| Catalog-only projection | `projectionSequence=0`. Compare `(ledgerRevision, projectionSequence)` only inside the bound host/profile/authority/epoch partition. |
| Same stored pair and same catalog digest | Same source value; accept a fresh read if all other gates pass. Timestamp regeneration may change `snapshotRevision`; it does not advance high-water. |
| Same stored pair, different `catalogDigest` | `source_equivocation`; no current snapshot and no high-water update. **Missing implementation proof:** pinned schema/admission accepts this today; durable equal-tuple digest comparison belongs to main/cache. |
| Lower source pair | `source_revision_regression`; no current snapshot. Pinned admission has a lower-pair check but no durable owner. |
| Newer pair | Commit `(revision, sequence, digest)` atomically only after full frame, UTF-8, strict semantic/digest, canonical-byte, and finite-admission checks. |
| `source.bind` without a complete validated read | Never seeds high-water. If a previously known partition has missing/corrupt history, stay unavailable pending explicit rebind; never silently treat it as first seen. Bootstrap/rebind authority remains open. |
| Source clock | For a read completed at `2026-09-30T01:00:00.000Z`, emit `staleAfter=2026-09-30T01:01:00.000Z`. The snapshot validator does not enforce this exact interval: the accepted pinned `snapshot.full` uses 11 minutes. Do not compare source timestamps with unverified Windows wall time. |
| Host current lifetime | Candidate only: 30,000 ms on Orca's monotonic clock; 29,999 ms may remain current, at 30,000 ms stale. App restart, lease retirement, binding change, or resume-from-suspend invalidates current until a fresh authenticated read. The current `fixedNow` admission helper is not cross-clock proof. |
| Snapshot payload bytes | Exactly 2,097,152 canonical UTF-8 bytes: accepted. 2,097,153: `snapshot_byte_limit_exceeded`, no partial snapshot. The pinned generator `snapshot-over-2mib` is the source fixture; an exact-limit variant was validated by trimming labels and recomputing `snapshotRevision`. |

## Verification and remaining proofs

Read-only validation used the built pinned contract exports: `validateTicketContractV1`, `validateTicketNavigatorSnapshotV1`, `digestRoleTransitionV1`, `digestCanonicalJsonV1`, and `digestNavigatorSnapshotV1`. The exact-cap and +1 boundary variants both used canonical serialization and a recomputed snapshot digest. No product files or pinned-submodule files were changed.

Still unproven: production ticket-ID-to-physical-host allowlist provenance; exact producer service version/artifact and one-read implementation; durable high-water bootstrap, equal-tuple equivocation, loss/corruption and explicit epoch rebind; host-monotonic current TTL and suspend/resume handling; live Orca binder/click-time same-read gating. The vectors do not make any ticket target matched or current.
