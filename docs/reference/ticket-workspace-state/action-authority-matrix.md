# TW-08 Action and Authority Matrix

**Status:** Contract-only survey. This matrix records source facts and proposed gates; it does not authorize implementation or effects. Snapshot: 2026-09-30.

**Labels:** **FACT** describes current source or an accepted plan. **DECISION PROPOSAL** is a safety contract for later ratification. **OPEN** needs an owner decision.

## Scope and shared gates

**FACT:** M6 names existing Orca workspace and agent actions. Its only explicit multi-stage action is ticket worktree removal, with archive, Orca removal, and external cleanup reported independently. The plan does not enumerate the exact workspace/agent RPC verbs. See [TW-08](./task-graph.md#L340) and [M6](./master-plan.md#L51).

**DECISION PROPOSAL:** Every action needs a live `current` TW-06 snapshot, TW-02L exact owner/host proof, and live TW-07 tree context. TW-07F fixture rows and fixture `mutationAllowed` outcomes never authorize an action. Stale, unavailable, or unsupported targets do not act. Only `isolated` ticket resources are effect targets; `referenced` stays read-only and `excluded` does not participate. Orca owns workspaces, Runs, workers, agent status, and Orca receipts; the ticket owner owns external-resource effects and adapter receipts. An Orca receipt records an Orca request/outcome; it never authorizes a ticket effect or substitutes for an adapter receipt. See the [ownership contract](./coordinator-root-authority.md#L34) and [active invariants](./review-findings.md#L14).

**DECISION PROPOSAL:** Revalidate the complete target immediately before each stage. Bind its preview digest and explicit confirmation to ticket authority/epoch/revision, snapshot revision, role, action, exact target, actual execution host, root Run/caller binding, and configured execution domain where relevant. Require a target-bound one-use root capability; it is only a TW-05G proposal today, and its issuer, TTL, transport, and consumption remain open. A renderer boolean is presentation, not authority. Do not infer a missing host from a path or accept an omitted legacy RPC host as attestation. See [TW-05G](./coordinator-root-authority.md#L147) and [TW-08 inputs/constraints](./task-graph.md#L347).

## Folder and remote target constraints

**FACT:** Ticket folder references have a different identity tuple from Git worktrees ([workspace identity](./coordinator-root-authority.md#L18)). Current folder registration can lack a host stamp, and path deduplication can return a Repo from another host; a path or returned record alone is not a complete ticket target ([review finding](./review-findings.md#L54)).

**DECISION PROPOSAL:** Keep folder workspaces in the M6 support contract, but leave a folder action unavailable until M3 proves actual host/storage route, stable directory identity, and exact Repo read-back; TW-02L separately supplies exact ticket owner/host proof. A Git ref/HEAD check does not apply to folders; use the ratified folder identity and preserve coordinator files instead. Do not silently route a folder target to another host.

**DECISION PROPOSAL:** For SSH or other remote routes, the execution host owns the operation. If the route is unsupported or contact is lost, report unavailable/unverifiable, preserve receipts/exclusion, and do not fall back locally. The MVP’s one-PC scope, including its planned Windows/WSL route, does not remove the requirement to preserve existing folder/SSH behavior.
